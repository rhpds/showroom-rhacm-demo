[[introduction]]
== Introduction

https://www.redhat.com/en/technologies/management/advanced-cluster-management[Red Hat Advanced Cluster Management] (RHACM) is Red Hat's enterprise software solution that allows IT teams to centrally manage, monitor, and scale fleets of Kubernetes and OpenShift clusters across data centers, cloud providers (like AWS, Azure, GCP), and edge environments from a single console. 
This demo covers the major use cases for Red Hat Advanced Cluster Management for Kubernetes: multicluster lifecycle, policy-driven governance, advanced application lifecycle, multicluster observability, business continuity, and AI-powered fleet management with OpenShift Lightspeed.

== What Users See

In this demo, you'll be provided with: 

* A Single-node OpenShift Cluster running the latest version of RHACM.
* A bastion machine with access to the ACM Hub cluster.
* An AWS Open Environment for executing some demo steps.

Some operations will require actions within the RHACM UI.
Others will require commands via the CLI.
Some may be doable in both ways. 
The demo steps will provided what's best suited for each case, and that means for each step/section, users might either see a embedded terminal tab, or an embedded OpenShift console page.

[[what-youll-learn]]
== What You'll Learn

After completing this lab, you will have gained comprehensive, hands-on experience with Red Hat Advanced Cluster Management (RHACM) across several key use cases.

* **Environment Preparation:** You will learn how to provision, configure, and access the RHACM Hub cluster using the Red Hat Demo Platform (RHDP).
* **Cluster Lifecycle Management:** You will discover how to create, import, and upgrade OpenShift clusters in a multi-cloud environment using AWS. This includes deploying standard Standalone clusters, resource-efficient Single Node OpenShift (SNO) clusters, and Hosted Control Plane clusters.
* **Application Lifecycle Management via GitOps:** You will learn how to install Argo CD and use it to manage multi-cluster applications. The lab covers utilizing a GitOps approach to distribute applications using a push model from a centralized cluster to remote target clusters.
* **Governance (GRC):** You will learn how to enforce security policies and ensure compliance across your entire fleet of clusters by creating and deploying policies within ACM, including the use of the Policy Generator.
* **End-to-End Observability:** You will configure centralized visibility to monitor cluster health and perform quick root cause analysis. This includes setting up backend storage (S3 buckets) and integrating Grafana into ACM for a complete observability overview.
* **Fleet Virtualization:** You will learn how to manage virtualization workloads from a single pane of glass using RHACM. This includes utilizing a centralized multi-cluster tree-view for enhanced visibility, creating new virtual machines across your clusters, and performing cross-cluster live migrations to simplify operations and reduce manual context switching.
* **Business Continuity:** You will learn how to protect critical workloads and ensure service availability across your multi-cluster fleet using RHACM. This includes configuring disaster recovery strategies, setting up cluster failover and failback procedures, and leveraging backup and restore capabilities to minimize downtime and maintain operational resilience in the event of cluster or infrastructure failures.
* **AI-Powered Fleet Management with OpenShift Lightspeed:** You will learn how to deploy the MCP server for Red Hat Advanced Cluster Management and configure OpenShift Lightspeed to query resources across your entire fleet using natural language. This includes deploying the MCP server via Helm, updating the OLSConfig custom resource, and using conversational queries to troubleshoot and analyze your managed clusters.

Before we get started we need to increase the max amount of pods for OpenShift, This will allow us to perform further use cases down the line. 

.Procedure
. From the Fleet Management Console Click on the *+ sign* -> *Import YAML* tab.
+
. Next, paste the following YAML and click *Create*
[source,bash,subs="+macros,+attributes",role=execute]
----
apiVersion: machineconfiguration.openshift.io/v1
kind: KubeletConfig
metadata:
  name: set-max-pods 
spec:
  machineConfigPoolSelector:
    matchLabels:
      pools.operator.machineconfiguration.openshift.io/master: "" 
  kubeletConfig:
    podsPerCore: 20 
    maxPods: 500
----

[[Foundational-Concepts]]
== Foundational Concepts/Glossary

* `Hub Cluster`: Also sometimes called the management cluster, is the OpenShift cluster in which RHACM is installed. The Hub cluster manages all managed clusters.
* `Managed Cluster`: Any kubernetes cluster that is registered to and is being managed by a RHACM Hub cluster.
* `OpenShift Cluster`: Essentially, a OpenShift instance. After you install OpenShift in a machine, or using multiple compute machines(also called nodes), you have an OpenShift cluster.
* `RHACM Console`: a.k.a, the RHACM web-based User Interface.
